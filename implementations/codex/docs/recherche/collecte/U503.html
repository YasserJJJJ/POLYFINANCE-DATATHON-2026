  • Automatisation des données

  • Automatisation des données

    Amazon Bedrock Data Automation transforme le contenu multimodal non structuré en formats de données structurées pour des cas d’utilisation tels que le traitement intelligent des documents, l’analyse vidéo et la génération à enrichissement contextuel (RAG). Bedrock Data Automation peut générer du contenu de sortie standard à l’aide de valeurs par défaut prédéfinies qui sont spécifiques à la modalité, comme des descriptions scène par scène de vidéos, des transcriptions audio ou une analyse automatique de documents. Les clients peuvent également créer des sorties personnalisées en spécifiant leurs exigences de sortie dans des plans en fonction de leur propre schéma de données, qu’ils peuvent ensuite facilement charger dans une base de données ou un entrepôt de données existant. Grâce à une intégration avec les bases de connaissances, Bedrock Data Automation peut également servir à analyser le contenu destiné aux applications de RAG, pour ainsi améliorer la précision et la pertinence des résultats en incluant des informations intégrées à la fois dans les images et le texte.

    Les bases de connaissances d’Amazon Bedrock proposent une intégration de Bedrock Data Automation afin de fournir des réponses plus pertinentes et plus précises pour les données multimodales. Lorsque vous configurez une base de connaissances, vous pouvez sélectionner Bedrock Data Automation comme méthode d’analyse pour analyser et extraire des informations pertinentes à partir d’images ou de documents, qui peuvent inclure des figures, des graphiques et des diagrammes. Au cours du traitement, Bedrock Data Automation extrait des informations pertinentes des documents et des images ingérés, qui sont ensuite utilisées dans les étapes suivantes de la base de connaissances pour le découpage, la vectorisation et le stockage. Lorsqu’elle est intégrée aux bases de connaissances, Bedrock Data Automation fournit et facture des résultats standardisés.

    Le routage intelligent des invites vous permet d’utiliser une combinaison de modèles de fondation (FM) de la même famille de modèles pour optimiser la qualité et les coûts. Le routeur des prompts prédit quel modèle fournira les meilleures performances pour chaque demande, tout en optimisant la qualité de la réponse et les coûts. Cette fonction est particulièrement utile pour les applications telles que les assistants de service client, où les requêtes simples peuvent être traitées par des modèles plus petits, plus rapides et plus rentables, et où les requêtes complexes sont acheminées vers des modèles plus performants. Le routage intelligent des invites peut réduire les coûts jusqu’à 30 % sans compromettre la précision.

  • Optimisation de prompt pour Amazon Bedrock

    Amazon Bedrock propose deux optimiseurs de prompt. 
    Optimiseur simple de prompt
    L’optimiseur simple de prompt est disponible en un seul clic dans le terrain de jeu et le Gestionnaire de prompt. Il est également disponible via l’API OptimizePrompt. Seuls le nombre total de jetons des prompts d’entrée et celui des prompts optimisés obtenus vous sont facturés. Le prix est de 0,03 USD pour 1 000 jetons

    Optimiseur avancé de prompt
    L’optimisation avancée des invites de Bedrock est disponible dans la section Optimisation avancée des prompts de la console Bedrock et via l’API CreateAdvancedPromptOptimizationJob. Les jetons de niveau standard à la demande utilisés lors de l’optimisation vous sont facturés. Pour estimer votre consommation, les points suivants sont importants : L’optimiseur de prompt utilise des LLM comme moteurs de réécriture et évaluateurs, qui fonctionnent en boucles itératives d’inférence, d’évaluation et de réécriture. Utilisez les équations suivantes pour estimer vos coûts, où N = le nombre d’enregistrements du jeu de données dans votre jeu de données d’évaluation pour chaque modèle de prompt, P = le nombre de jetons d’entrée dans vos modèles de prompt, O = le nombre estimé de jetons de sortie du modèle cible et G = le nombre de jetons de la réponse de référence de vérité terrain.

    Évaluateur de fonction Lambda : Si vous choisissez d’utiliser une fonction Lambda comme évaluateur, vous pouvez estimer le nombre total de jetons et le coût par modèle de prompt à l’aide des formules suivantes : 
    Invocations Lambda par modèle de prompt = 16*N. 
    Nombre total de jetons du modèle cible = 16*N*(P+O). 
    Nombre de jetons d’entrée du LLM de l’optimiseur (actuellement Anthropic Claude Sonnet 4.6) = 101 * (3 700+0,35P). 

    Évaluateur LLM-juge : Si vous choisissez l’option LLM-juge ou l’option de critères de pilotage en langage naturel, vous pouvez estimer le nombre total de jetons par modèle de prompt à l’aide des formules suivantes Nombre total de jetons du modèle cible = 16*N*(P+O). 
    Nombre de jetons d’entrée du LLM de l’optimiseur (actuellement Anthropic Claude Sonnet 4.6) = 101 * (3 700+0,35P). 
    Nombre de jetons LLM-juge = 16*N*(P+O+G + prompt juge)

    Remarque : Il s’agit d’une fonctionnalité d’IA générative : le nombre exact de jetons de sortie n’est connu qu’au moment de l’exécution et varie en fonction de ce que le prompt doit produire.
