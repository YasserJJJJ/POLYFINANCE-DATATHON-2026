Document history for the Amazon Bedrock User Guide

The following table describes important changes in each release of Amazon Bedrock. For notification about updates to this documentation, you can subscribe to an RSS feed.

ChangeDescriptionDate

November 4, 2026

New topic: Watermarking in Amazon Bedrock

Added a topic that lists the models in Amazon Bedrock that add a watermark to their output and describes how to detect the watermark. For more information, see Watermarking in Amazon Bedrock.

October 30, 2026

Clarified when Advanced Prompt Optimization prompt shortening returns the original prompt

Clarified that prompt shortening depends on your evaluation. If the original prompt already scores at the maximum on your evaluation samples, or if the samples do not distinguish between candidate prompts, the original prompt is returned with a compression ratio of 1.0. Added guidance on choosing evaluation samples that give the optimizer room to improve. Updated the Shorten prompts page and the Troubleshooting page.

October 26, 2026

Clarified batch inference completion behavior and quotas

Clarified on the Capacity and Performance page that on-demand requests are prioritized over batch inference jobs and that job completion is not guaranteed. Added the default and maximum job timeout (24 hours by default, up to 168 hours). Replaced the fixed job size and file size values with a link to the batch inference quotas in the AWS General Reference. Updated the Capacity and Performance page and the Create a batch inference job page.

October 26, 2026

Distribute private offers from AWS Marketplace

You can now distribute private offers for third-party models in Amazon Bedrock to your organization on the AWS Marketplace purchase confirmation page, right after you accept the offer. For all other subscriptions, continue to distribute through AWS License Manager. For more information, see Distribute through AWS Marketplace.

October 22, 2026

Advanced Prompt Optimization supports prompt shortening and application inference profiles

You can enable prompt shortening per prompt template to reduce prompt length while maintaining or improving evaluation scores. Application inference profiles are accepted as target models and judge models. Results include median time to first token and average and median latency. For more information, see Shorten prompts.

October 20, 2026

Retrieval instructions for Amazon Bedrock agentic retrieval

Agentic retrieval on fully managed Amazon Bedrock knowledge bases now supports retrieval instructions. A retrieval instruction steers how the agent searches your knowledge bases and how it answers. Amazon Bedrock reviews each instruction before it takes effect, and you can pin an immutable version. Use the retrievalInstructionConfiguration field on AgenticRetrieveStream to apply one. For more information, see Create and manage retrieval instructions.

October 19, 2026

Contextual grounding checks support safeguard tiers

Amazon Bedrock Guardrails contextual grounding checks now support Standard tier. Standard tier supports responses that include reasoning or conversational content, returns more consistent scores, and supports additional languages. For more information, see Use contextual grounding check to filter hallucinations in responses and Safeguard tiers for guardrails policies.

October 19, 2026

Structured outputs now available for Anthropic Claude models on both endpoints

Structured outputs is now available for Anthropic Claude models on both the bedrock-runtime and bedrock-mantle endpoints. Added a Claude-focused Structured outputs for Anthropic Claude models page, updated the Structured outputs page, and updated the affected Claude model cards.

September 1, 2026

Corrected Claude Sonnet 5 thinking guidance: adaptive thinking is on by default and can be disabled

Corrected the Reasoning entry on the Claude Sonnet 5 model card, which incorrectly stated that adaptive thinking is always on and cannot be disabled. On Claude Sonnet 5, adaptive thinking is on by default — including for requests that omit the thinking field — and can be turned off by passing "thinking": {"type": "disabled"}. Added Claude Sonnet 5 to the supported models table on the Adaptive thinking topic, and added guidance covering the default-on behavior change from Claude Sonnet 4.6, the fact that only the explicit disabled thinking type turns thinking off (omitting the thinking field selects adaptive thinking, and budget_tokens is not supported on this model), that thinking tokens are billed as output tokens, and the need to revisit max_tokens for workloads migrated from Claude Sonnet 4.6.

August 24, 2026

Fixed Anthropic Messages API code samples and switched model-card OpenAI-SDK samples to bedrock-runtime

Fixed the Anthropic Messages API Python sample on the Overview page, which previously used anthropic.Anthropic() with no base URL and failed with a validation exception. Every Anthropic Messages API Python sample now uses the plain Anthropic client from the Anthropic SDK, targets the bedrock-runtime endpoint's /anthropic route directly with base_url="https://bedrock-runtime.{region}.amazonaws.com/anthropic", and authenticates with a short-term Amazon Bedrock bearer token generated by aws-bedrock-token-generator's provide_token(). Updated the Sample Code section of every Anthropic model card that supports bedrock-runtime (Claude Opus 5, Opus 4.8, Opus 4.7, Sonnet 5, Haiku 4.5, and Fable 5) to use this pattern with the model's Global inference ID, and updated the corresponding pip install line to pip install -U anthropic aws-bedrock-token-generator. Updated the same sample on the Quickstart page, the Messages API topic, and the Tool use reference topic. Reordered the code sample tabs on the Messages API topic to lead with bedrock-runtime variants (Anthropic SDK, boto3, AWS CLI, curl) and moved the bedrock-mantle curl tab to the end. Repointed the OPENAI_BASE_URL environment variable on 49 non-Anthropic model cards (OpenAI, Mistral AI, DeepSeek, Google, Meta, Qwen, MiniMax, NVIDIA, Moonshot AI, Z.AI, Writer, xAI) from the bedrock-mantle /v1 route to the bedrock-runtime /openai/v1 route (https://bedrock-runtime.{region}.amazonaws.com/openai/v1) so the Responses API and Chat Completions API samples in the Sample Code section run against bedrock-runtime by default. The bedrock-mantle endpoint continues to be fully supported and pages that document mantle-only features (Web Search, Projects, Workspaces, Chat Completions on mantle, the mantle Responses API page) still show bedrock-mantle URLs.

August 19, 2026

Changes include reordered quickstart tabs and code samples on the Overview and Quickstart pages, reordered endpoint and API guidance on the Endpoints, APIs, and Build pages, reordered Programmatic Access sections in model cards, retitled the Responses API and Chat Completions API pages that document the bedrock-mantle variants, and added cross-reference tips on the Projects and Workspaces pages. The bedrock-mantle endpoint continues to be fully supported and existing applications that use it do not need to change.

August 15, 2026

AgentCore Memory integration for Amazon Bedrock agentic retrieval

Agentic retrieval on fully managed Amazon Bedrock knowledge bases now integrates with Amazon Bedrock AgentCore Memory. Use the memoryConfiguration field on AgenticRetrieveStream to configure memory. You can restore an earlier session from short-term memory, let the agent retrieve memory records from long-term memory, or both. For more information, see Use agentic retrieval to query a knowledge base.

August 14, 2026

IAM principal cost allocation now supported on the bedrock-mantle endpoint

Amazon Bedrock now supports cost allocation by IAM principal (users and roles) for inference requests made through the bedrock-mantle endpoint, extending the capability previously available for bedrock-runtime. Tag IAM users and roles with attributes such as team, project, or cost center, activate them as cost allocation tags, and analyze bedrock-mantle inference costs by those tags in AWS Cost Explorer or at the line-item level in AWS Cost and Usage Report 2.0 (CUR 2.0). Available in all AWS Regions where the bedrock-mantle endpoint is available. For more information, see IAM principal attribution in Amazon Bedrock.

June 30, 2026

Updated requests-per-minute (RPM) quota guidance

Clarified RPM quota behavior across Amazon Bedrock endpoints. The bedrock-mantle endpoint does not expose per-model RPM quotas; throttling is governed by token-based quotas. On the bedrock-runtime endpoint, RPM quotas are model-specific — some models, including Anthropic Claude Opus 4.7 and Claude Opus 4.8, are not subject to an RPM quota. For models that do have an RPM quota, see the Service Quotas console.
