Semantic conventions for generative AI systems

 Status : Development 

Semantic conventions for Generative AI operations are defined for the following signals:

 Client Inference : Semantic Conventions for Generative AI inference operations - spans, events, and metrics .

 Client Embeddings : Semantic Conventions for Generative AI embeddings operations - spans, events, and metrics .

 Execute Tool : Semantic Conventions for Generative AI tool execution - spans, events, and metrics .

 Retrieval : Semantic Conventions for Generative AI retrieval operations - spans and metrics .

 Client Agent Invocations : Semantic Conventions for Generative AI remote agent invocations - spans and metrics .

 Events : Semantic Conventions for Generative AI inputs and outputs - events .

 Exceptions : Semantic Conventions for Generative AI exceptions .

 Metrics : Semantic Conventions for Generative AI operations - metrics .

 Inference Token Metrics : Semantic Conventions for Generative AI inference token metrics - metrics .

 Model spans : Semantic Conventions for Generative AI model operations - spans and events .

 Realtime content generation : Semantic Conventions for Generative AI realtime, bidirectional streaming operations.

 Agent spans : Semantic Conventions for Generative AI agent operations - spans and events .

Technology specific semantic conventions are defined for the following GenAI system:

 Anthropic : Semantic Conventions for Anthropic.

 Azure AI Inference : Semantic Conventions for Azure AI Inference.

 AWS Bedrock : Semantic Conventions for AWS Bedrock.

 OpenAI : Semantic Conventions for OpenAI.

See also:

 Agent2Agent Protocol : Semantic Conventions for A2A 

 Model Context Protocol : Semantic Conventions for MCP 

Attributes shared across operations

Instrumentations MAY propagate context containing attributes listed below to nested
instrumentations within the same process. This allows queries to select related
spans without traversing the hierarchy.

When an attribute is available both from the instrumented library and from outer
context, instrumentation SHOULD prefer the library's value.

Instrumentations SHOULD NOT propagate attributes not listed here.
Instrumentations SHOULD NOT use these attributes on signals that don't reference them
explicitly.
