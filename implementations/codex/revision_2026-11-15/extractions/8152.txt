Vous avez besoin d'une seule API : Converse. Elle fonctionne de la même façon pour tous les modèles de texte d'Amazon Bedrock, ce qui vous permet de changer de
modèle sans réécrire votre code. Utilisez-la et ignorez l'ancienne API InvokeModel, qui demande un format de requête différent pour chaque fournisseur.

Relisez les réponses. Lors de nos tests, Nova 2 Lite a décrit ce bêta de 1,8 comme « 80 % plus volatil que le S&P 500 ». C'est inexact : le bêta mesure la sensibilité aux

Converse est sans état. Le modèle ne garde aucune mémoire entre deux appels : pour poursuivre une conversation, vous renvoyez tout l'historique à chaque appel.
C'est le malentendu le plus fréquent chez les nouveaux utilisateurs de l'API.
Si la deuxième réponse mentionne une tolérance au risque élevée, votre gestion de l'historique fonctionne.
En démonstration, un texte qui s'affiche au fur et à mesure semble beaucoup plus rapide que le même texte qui arrive d'un bloc après quatre secondes. Le streaming
n'est disponible qu'avec un SDK : l'AWS CLI n'a pas de commande converse-stream.
Une application a souvent besoin de données, pas de prose. Si vous donnez un schéma JSON à Bedrock, la réponse respecte ce schéma : c'est la fonction de sorties
structurées (structured outputs). Bedrock contraint le décodage du modèle selon votre schéma, et la réponse se lit avec json.loads du premier coup.

Trois points à connaître :
Le schéma est passé sous forme de chaîne. Utilisez json.dumps(SCHEMA), pas le dictionnaire.
additionalProperties: false est obligatoire, et certaines fonctions de JSON Schema ne sont pas prises en charge : pas de minLength, de maximum ni de
schémas récursifs.
Le premier appel avec un nouveau schéma peut être plus lent. Bedrock compile une grammaire, puis la garde en cache pendant 24 heures. Faites un appel de test
avant votre démonstration.
Vous pouvez aussi ajouter "strict": True à une déﬁnition d'outil dans toolConfig, ce qui verrouille les arguments que le modèle passe à votre outil. C'est la
même garantie, appliquée aux agents.
Voici les erreurs que vous rencontrerez vraiment.
ValidationException: Invocation of model ID <id> with on-demand throughput isn't supported
Le modèle exige un proﬁl d'inférence et vous avez utilisé l'identiﬁant sans préﬁxe. Ajoutez le préﬁxe global. ou us. :
Voir Choisir un modèle pour savoir quels modèles l'exigent.
ValidationException: ... temperature is deprecated for this model (ou top_p)
Claude Sonnet 5, Opus 5 et Opus 5.5 refusent les paramètres temperature et topP. Retirez-les de inferenceConfig et gardez seulement maxTokens. Nova 2 Lite,
Claude Haiku 4.5 et Claude Sonnet 4.6 les acceptent.
ValidationException: The provided model identifier is invalid
Souvent une faute de frappe, ou un modèle qui n'existe pas dans votre région. Vériﬁez dans votre propre compte :
AccessDeniedException
Le plus souvent, c'est le tout premier appel à un modèle Anthropic dans un compte neuf, pendant qu'une étape unique au niveau du compte se propage. Attendez
deux minutes et réessayez. Si l'erreur persiste, essayez un modèle Amazon Nova. Si Nova fonctionne et pas Claude, c'est cette étape du compte : un mentor AWS peut
vous aider.
ThrottlingException
Vous appelez plus vite que le quota du compte ne le permet. Réessayez avec un délai croissant (backoff exponentiel) plutôt qu'immédiatement. Conﬁgurez boto3
pour qu'il le fasse à votre place :
ExpiredTokenException ou InvalidClientTokenId
Vos identiﬁants temporaires ont expiré. Récupérez-en de nouveaux depuis la page de l'événement dans Workshop Studio, ou utilisez CloudShell, qui s'en occupe pour
vous. Voir Accès AWS CLI et SDK.
Le texte de la réponse est vide ou content[0]["text"] lève une KeyError
Vous avez appelé un modèle qui peut renvoyer deux blocs de contenu : son raisonnement d'abord (reasoningContent), puis la réponse (text). C'est le cas
d'openai.gpt-oss-120b-1:0, de Claude Sonnet 5 et de Claude Opus 5.5. Cherchez le bloc de texte par son nom, pas par sa position :
Ce code fonctionne avec tous les modèles : prenez cette habitude. Si le texte est vide et que stopReason vaut max_tokens, le raisonnement a utilisé tous les tokens
: augmentez maxTokens.

Les paramètres --messages, --system et --inference-config doivent être passés en JSON. La syntaxe abrégée (shorthand) de l'AWS CLI ne fonctionne pas pour eux.
En Python
import boto3
from botocore.exceptions import ClientError
client = boto3.client("bedrock-runtime", region_name="us-east-1")
MODEL_ID = "global.amazon.nova-2-lite-v1:0"
SYSTEM = (
    "Vous êtes un analyste financier pédagogue. Vous expliquez des notions à des fins éducatives, "
    "sans jamais donner de conseil financier personnalisé. Soyez concis et factuel."
)
try:
    response = client.converse(
        modelId=MODEL_ID,
        system=[{"text": SYSTEM}],
        messages=[
            {
                "role": "user",
                "content": [{"text": (
                    "Persona : investisseur Prudent (tolérance au risque faible). "
                    "Expliquez ce que signifie un drawdown maximal de -34 % pour le FNB QQQ "
                    "sur la période 2020-2024, en trois phrases."
                )}],
            }
        ],
        inferenceConfig={"maxTokens": 500, "temperature": 0.3},
    )
    # Concaténer les blocs de texte : certains modèles renvoient d'abord un bloc de raisonnement
    blocks = response["output"]["message"]["content"]
    print("".join(b["text"] for b in blocks if "text" in b))
    print("---")
    print("Tokens :", response["usage"])
    print("Latence (ms) :", response["metrics"]["latencyMs"])
    print("Raison d'arrêt :", response["stopReason"])
except ClientError as e:
    print(f"L'appel à {MODEL_ID} a échoué : {e}")

Tenir une conversation
import boto3
client = boto3.client("bedrock-runtime", region_name="us-east-1")
MODEL_ID = "global.amazon.nova-2-lite-v1:0"
messages = []
def ask(question: str) -> str:
    messages.append({"role": "user", "content": [{"text": question}]})
    response = client.converse(
        modelId=MODEL_ID,
        messages=messages,
        inferenceConfig={"maxTokens": 500},
    )
    reply = response["output"]["message"]
    messages.append(reply)          # garder la réponse du modèle dans l'historique
    return "".join(b["text"] for b in reply["content"] if "text" in b)
print(ask("Nous travaillons avec le persona Audacieux (tolérance au risque élevée). Retenez-le et répondez seulement « Noté »."))
print(ask("Quelle est la tolérance au risque de notre persona ? Une phrase."))

import json
import boto3
client = boto3.client("bedrock-runtime", region_name="us-east-1")
NEWS = """La Banque Royale du Canada a publié un bénéfice net trimestriel de 4,5 milliards de dollars,
en hausse de 12 % sur un an, porté par la gestion de patrimoine. La banque a toutefois augmenté
ses provisions pour pertes sur créances, citant un ralentissement de l'économie canadienne."""
SCHEMA = {
    "type": "object",
    "properties": {
        "sentiment": {"type": "string", "enum": ["positif", "neutre", "negatif"]},
        "tickers": {"type": "array", "items": {"type": "string"}},
        "faits_chiffres": {"type": "array", "items": {"type": "string"}},
        "risques_mentionnes": {"type": "array", "items": {"type": "string"}},
    },
    "required": ["sentiment", "tickers", "faits_chiffres", "risques_mentionnes"],
    "additionalProperties": False,
}
response = client.converse(
    modelId="global.anthropic.claude-haiku-4-5-20251001-v1:0",
    messages=[{"role": "user", "content": [{"text": f"Analysez cette nouvelle financière :\n{NEWS}"}]}],
    inferenceConfig={"maxTokens": 500},
    outputConfig={"textFormat": {"type": "json_schema", "structure": {"jsonSchema": {
        "name": "analyse_nouvelle",
        "description": "Signaux structurés extraits d'une nouvelle financière",
        "schema": json.dumps(SCHEMA),   # attention : une *chaîne* JSON, pas un dict
    }}}},
)
blocks = response["output"]["message"]["content"]
data = json.loads("".join(b["text"] for b in blocks if "text" in b))
print(json.dumps(data, indent=2, ensure_ascii=False))
print("Sentiment :", data["sentiment"])
