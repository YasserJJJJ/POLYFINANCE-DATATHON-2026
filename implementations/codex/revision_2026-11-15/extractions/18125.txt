Étape 2 : donner les règles du projet, une seule fois
Crée un fichier CLAUDE.md dans ce dossier avec ces règles de projet :
- La région AWS est toujours us-east-1.
- Utilise Amazon Bedrock via boto3 et l'API Converse. N'utilise jamais InvokeModel.
- Modèle par défaut : global.amazon.nova-2-lite-v1:0
- Pour les étapes qui demandent plus de raisonnement : global.anthropic.claude-sonnet-5
- Dans une réponse Converse, ne lis jamais content[0]["text"] : concatène tous les
  blocs qui contiennent "text". Certains modèles renvoient d'abord un bloc de raisonnement.
- Données de marché : yfinance pour les prix, API Valet de la Banque du Canada pour FXUSDCAD.
  Mets les données téléchargées en cache dans data/ (CSV) pour que la démo fonctionne
  même si le réseau est lent.
- Chaque chiffre affiché indique sa source et sa date.
- Les profils d'investisseurs (Prudent, Équilibré, Audacieux) sont fictifs et vivent
  dans profiles.py.
- Simulation uniquement : aucune transaction réelle, aucun conseil financier personnalisé.
  L'application affiche un avertissement en ce sens.
- Prototype de datathon : une démo qui fonctionne passe avant les couches d'abstraction.
- La démo se lance avec : streamlit run app.py --server.address localhost

Étape 3 : demander l'application
Construis une application Streamlit app.py qui aide à comprendre le risque d'un actif
selon un profil d'investisseur.
Comportement :
- Un sélecteur de persona (Prudent, Équilibré, Audacieux) et une zone de texte où
  l'utilisateur pose une question, par exemple « XIU.TO ou SPY pour un profil prudent
  sur 3 ans ? Compare en dollars canadiens. »
- Appelle Amazon Bedrock avec l'API Converse et donne au modèle deux outils :
    get_risk_metrics(symbol, years) -> rendement annualisé, volatilité annualisée et
      perte maximale, calculés sur la clôture ajustée (yfinance)
    get_usdcad(date) -> taux FXUSDCAD de la Banque du Canada à cette date ou avant
- Le modèle explique ce que les chiffres signifient pour le persona choisi, en séparant
  les faits (chiffres calculés), les hypothèses et les limites.
- Affiche la réponse, puis en dessous les outils appelés, leurs arguments et leurs
  résultats, pour qu'on voie d'où viennent les chiffres.
- Gère les erreurs (symbole inconnu, réseau indisponible) sans afficher de trace brute.
Crée requirements.txt, installe les dépendances, puis lance l'application et corrige
tout ce qui casse jusqu'à ce qu'elle fonctionne.
