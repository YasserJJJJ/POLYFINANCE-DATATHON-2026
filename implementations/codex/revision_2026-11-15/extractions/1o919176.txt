Codex sur Bedrock
Codex est l'outil de programmation agentique d'OpenAI. Il peut utiliser des modèles OpenAI hébergés sur Amazon Bedrock : il passe alors par le compte AWS de votre
équipe, et vos requêtes ne transitent pas par l'API hébergée par OpenAI.
Ses fonctions recoupent largement celles de Claude Code. Choisissez-en un et apprenez à bien vous en servir, plutôt que de changer d'outil en plein Datathon.
Codex CLI 0.128.0 ou plus récent (ou application de bureau / extension VS Code 26.429.30905 ou plus récente)
Accès à un modèle OpenAI pris en charge dans votre compte Bedrock
Des identiﬁants AWS valides : sur votre ordinateur, copiez les identiﬁants AWS CLI temporaires depuis la page de l'événement Workshop Studio ; dans
CloudShell 
, ils sont déjà en place
Codex sur Bedrock n'accepte que ces identiﬁants exacts :
openai.gpt-5.6-sol
Choix recommandé par défaut
openai.gpt-5.6-terra
openai.gpt-5.6-luna
openai.gpt-5.5
openai.gpt-5.4
Bedrock propose aussi des modèles OpenAI plus récents (par exemple openai.gpt-6-sol), mais ils ne ﬁgurent pas dans la liste officielle de Codex au 4 novembre
2026. Restez sur la liste ci-dessus pour Codex.
Vériﬁez ce que votre compte propose avant de conﬁgurer quoi que ce soit :
Si aucun des cinq identiﬁants pris en charge n'apparaît, Codex sur Bedrock n'est pas possible dans votre compte : utilisez Claude Code ou Kiro.
Créez ou modiﬁez ~/.codex/config.toml :
Déﬁnir la région dans ce ﬁchier est l'option la plus explicite. Sinon, Codex laisse le SDK AWS trouver la région (AWS_REGION, puis AWS_DEFAULT_REGION, puis votre
proﬁl).
Codex vériﬁe deux méthodes, dans cet ordre :
1. AWS_BEARER_TOKEN_BEDROCK : une clé d'API Bedrock
2. La chaîne d'identiﬁants standard du SDK AWS
Avec les identiﬁants AWS (le cas habituel pendant le Datathon), tout ce que le SDK AWS comprend fonctionne : variables d'environnement copiées depuis Workshop
Studio, ﬁchier d'identiﬁants partagé ou proﬁl nommé :
Vous pouvez aussi ﬁxer le proﬁl dans la conﬁguration :
Avec une clé d'API Bedrock :
Avec une clé d'API, la région doit être déﬁnie dans config.toml.
Vériﬁez que le fournisseur de modèle affiché est amazon-bedrock.
Les applications graphiques n'héritent pas forcément des variables de votre shell. Mettez-les dans ~/.codex/.env :
Redémarrez l'application ou l'extension après chaque modiﬁcation de config.toml ou de .env.
Codex lit AGENTS.md à la racine de votre projet :
Pour ne pas perdre de temps à essayer : génération d'images, transcription vocale en entrée, boutique de plugins infonuagique, conﬁguration et politiques
infonuagiques, agents infonuagiques (dont les agents de revue, de sécurité et web).
Vériﬁez dans l'ordre :
Votre version de Codex respecte le minimum.
Votre identiﬁant de modèle correspond exactement à l'un des cinq identiﬁants pris en charge, sans préﬁxe.
Le modèle est disponible dans la région conﬁgurée.
Vos identiﬁants ou votre clé d'API sont valides et n'ont pas expiré. Les identiﬁants Workshop Studio sont temporaires.
Pour l'application de bureau ou l'extension, les variables sont dans ~/.codex/.env et vous avez redémarré.
