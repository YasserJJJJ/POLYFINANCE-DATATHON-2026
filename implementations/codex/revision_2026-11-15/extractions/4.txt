Veuillez suivre ces règles quand vous travaillez dans votre environnement AWS. Ne pas les respecter peut entraîner la suspension du compte de votre équipe.
1. NE CRÉEZ PAS de bucket S3 sans restriction d'accès. Gardez S3 Block Public Access 
 activé, ce qui est le réglage par défaut.
2. NE CRÉEZ PAS d'instance EC2 avec un groupe de sécurité ouvert à Internet 
.
3. NE CRÉEZ PAS d'instance RDS ni de cluster EMR avec l'accès public activé.
4. NE METTEZ PAS d'identiﬁants AWS dans un dépôt Git. Si une clé d'accès se retrouve sur GitHub, considérez qu'elle est compromise en quelques minutes.
5. LIMITEZ les ressources que vous lancez à ce dont votre projet a vraiment besoin, et arrêtez tout ce que vous n'utilisez pas.
Utilisez des données publiques ou ﬁctives. Le déﬁ l'exige : aucun compte client réel, aucun renseignement bancaire conﬁdentiel, aucune donnée personnelle. Les
proﬁls d'investisseurs et les portefeuilles peuvent être entièrement ﬁctifs.
Respectez aussi les conditions d'utilisation de chaque source de données publique. Voir Données ﬁnancières publiques.
Votre prototype n'exécute aucune transaction réelle et ne se présente pas comme un conseil ﬁnancier personnalisé. Ne connectez aucun outil ni aucun agent à un
compte de courtage. Un garde-fou Amazon Bedrock peut vous aider à respecter cette règle.
Tous les modèles disponibles dans Amazon Bedrock sont permis pendant le Datathon.
Amazon Bedrock applique des quotas d'appels par compte. Vous n'avez pas à vous imposer un débit artiﬁciel, mais votre code doit bien se comporter quand il atteint
une limite :
Gérez ThrottlingException avec des tentatives et un délai croissant. Les SDK AWS le font pour vous si vous conﬁgurez un mode de tentatives : voir le
comportement des tentatives 
. Un agent peut facilement faire des dizaines d'appels de modèle pour répondre à une question.
Préférez un proﬁl d'inférence global. quand il existe pour votre modèle. Il répartit les requêtes entre plus de régions, ce qui donne plus de capacité et moins
d'erreurs de limitation quand toute la salle travaille en même temps. Voir Choisir un modèle.
N'exécutez pas de boucle sans limite contre un modèle. Un agent coincé dans une boucle de tentatives pendant la nuit est le moyen le plus rapide d'épuiser le
quota de toute votre équipe.
Commencez avec un petit modèle. global.amazon.nova-2-lite-v1:0 est rapide et peu coûteux, et suffit pour prouver que votre idée fonctionne. Passez à un
modèle plus grand seulement quand vous pouvez montrer une erreur du petit.
L'accès aux modèles d'Amazon Bedrock est activé par défaut : il n'y a plus de page « Model access » à visiter ni de demande à soumettre pour les modèles serverless
standards.
Quelques points peuvent quand même vous bloquer :
Le premier appel à un modèle Anthropic dans un compte neuf peut exiger un formulaire de première utilisation, une seule fois pour le compte, et l'abonnement
peut prendre quelques minutes à s'activer. Si un premier appel à Claude échoue avec AccessDeniedException, attendez quelques minutes et réessayez, puis
demandez à un mentor. Faites ce premier appel depuis CloudShell ou la console (voir Commencer), pas depuis SageMaker Uniﬁed Studio.
Les modèles Amazon n'ont pas cette étape, une raison de plus de commencer avec Amazon Nova.
Certains modèles sont restreints par les conditions de leur fournisseur, par région ou à certains clients. Si un modèle n'apparaît pas dans votre compte, il ne vous
est pas disponible : choisissez-en un autre.
La réponse qui fait foi pour votre compte vient toujours du compte lui-même :
